ВВЕДЕНИЕ
В современной производственной и торговой среде, где стоимость сырья напрямую влияет на конечную цену продукции и рентабельность бизнеса, оперативный мониторинг цен является ключевой задачей. Рынок металлопродукции отличается высокой волатильностью, и ручное отслеживание цен на десятках и сотнях страниц сайтов-поставщиков является трудоемким, медленным и подверженным ошибкам процессом.
Компания i5.solutions столкнулась с необходимостью автоматизировать сбор данных с сайта одного из ключевых поставщиков —23met.ru— для анализа динамики цен и планирования закупок.
Целью настоящей практики являлась разработка программного комплекса для автоматического сбора, обработки и структурирования данных о ценах на металлопродукцию с сайта 23met.ruдля последующего анализа и мониторинга.
Для достижения поставленной цели были определены следующие задачи:
Изучить структуру целевого сайта, выявить источники данных и методы их защиты от автоматического сбора;
Разработать скрипт для автоматического поиска всех релевантных страниц с прайс-листами;
Реализовать асинхронный парсер для эффективного извлечения данных;
Создать модуль постобработки для очистки и приведения данных к структурированному виду, готовому для анализа;
Настроить систему для автоматического ежедневного запуска.


1 Анализ и постановка задачи
1.1 Бизнес-проблема и цели проекта
Ключевой проблемой, решаемой в рамках данной практики, является необходимость в получении актуальных и структурированных данных о ценах на металлопродукцию для компании-партнера i5.solutions. Ручной сбор данных с сайта 23met.ru, являющегося важным источником информации, неэффективен по ряду причин:
Большой объем данных: Сайт содержит множество разделов и подразделов, каждый с собственными таблицами цен, что делает ручной мониторинг крайне трудоемким.
Высокая динамичность цен: Стоимость металлопродукции может меняться ежедневно, что требует постоянного и оперативного отслеживания.
Целью проекта является разработка автоматизированного программного комплекса, который будет выполнять полный цикл сбора, обработки и структурирования данных с целевого сайта, подготавливая их для дальнейшего анализа и использования в бизнес-процессах компании.
1.2 Анализ предметной области
В ходе предварительного анализа сайта 23met.ru были выявлены технические особенности, которые необходимо было учесть при проектировании системы:
Структура данных: Вся необходимая информация (наименование товара, ГОСТ, сталь, размеры, цена) представлена в виде стандартных HTML-таблиц, что упрощает их программный разбор.
Защита от парсинга: При большом количестве последовательных запросов с одного IP-адреса сайт активирует систему защиты (CAPTCHA), что приводит к временной блокировке доступа. Этот фактор делает обязательным использование механизмов обхода ограничений.
Неявная структура навигации: Для полного охвата ассортимента продукции недостаточно простого обхода ссылок с главной страницы. Необходимо было разработать метод для обнаружения всех скрытых или динамически подгружаемых страниц с прайс-листами.

1.3 Организация рабочего процесса
Прохождение производственной практики было организовано на базе кафедры ИУ6 МГТУ им. Н.Э. Баумана при кураторстве со стороны компании-партнера i5.solutions. Рабочий процесс был выстроен в формате проектной деятельности с регулярными консультациями с руководителем.
На установочной встрече была определена основная бизнес-задача, стоящая перед компанией, а именно — необходимость в автоматизации сбора и анализа данных о ценах на рынке металлопродукции для оптимизации закупочной деятельности. По итогам встречи было сформировано и выдано техническое задание, в котором были зафиксированы ключевые цели, задачи и требования к итоговому программному продукту.
Дальнейшая работа велась в самостоятельном режиме, что способствовало развитию навыков автономного решения инженерных задач. При этом была обеспечена возможность получения оперативной консультационной поддержки от руководителя при возникновении технических или методологических вопросов. 
Результатом проделанной работы стал программный комплекс, реализованный на языке Python. Для демонстрации и проверки выполнения задания весь исходный код, документация и сопутствующие материалы были размещены в репозитории на платформе GitHub. Доступ к репозиторию был предоставлен руководителю для проведения финальной проверки и оценки.
Все поставленные в рамках технического задания задачи были выполнены в полном объеме и в установленные сроки.

2 Проектирование
Для решения поставленной задачи был спроектирован пайплайн, состоящий из нескольких независимых, но последовательно выполняемых модулей:
Модуль GoogleParser: Использует внешний сервис ScraperAPI для выполнения поисковых запросов в Google (site:23met.ru прайс-лист). Это позволяет получить полный список URL-адресов всех страниц с прайс-листами, решая проблему их обнаружения.
Модуль ProxyParser: Опциональный модуль, который парсит бесплатные прокси-серверы с сайта proxylib.com и проверяет их на работоспособность с целевым сайтом.
Основной парсер ParserSite_23MET: Получает список URL-адресов и, при необходимости, прокси. Асинхронно (asyncio, aiohttp) отправляет запросы к каждой странице, скачивая HTML-код. После этого, с помощью BeautifulSoup, он извлекает необработанные табличные данные и сохраняет их в промежуточный CSV-файл (result.csv).
Модуль предобработки PreProcessor: Загружает "сырые" данные из result.csv и выполняет их очистку и структурирование. Этот модуль является ключевым для получения качественных данных.
Планировщик Cron: Системная утилита Linux, которая по заданному расписанию (например, каждый день в 12:00) запускает главный скрипт main.py, обеспечивая полную автоматизацию процесса.
Для наглядной демонстрации логики работы системы и движения информационных потоков были построены диаграммы потоков данных (DFD) в нотации Йордана. На Рисунке 1 представлена контекстная диаграмма потоков данных (DFD) разработанной системы. Она демонстрирует взаимодействие системы с внешним окружением на самом высоком уровне абстракции, представляя ее как единый процесс "Система парсинга и обработки данных 23met.ru".

- Google Search (через посредника ScraperAPI) для получения списка URL-адресов страниц с прайс-листами.

Далее, рассмотрим архитектуру системы с помощью UML-диаграммы классов, который можно увидеть на Рисунке 3. Центральным элементом архитектуры является абстрактный базовый класс Parser. Он определяет общий интерфейс и базовую логику для всех модулей, занимающихся сбором данных. Такой подход позволяет легко расширять систему: для парсинга нового сайта достаточно создать новый класс-наследник, который будет реализовывать специфичную для этого сайта логику.
Класс Parser использует принцип композиции, делегируя низкоуровневые задачи по работе с файлами и сетью специализированным классам-помощникам:
WorkerWithHtml инкапсулирует всю логику отправки HTTP-запросов, работы с User-Agent и прокси.
WorkerWithFiles отвечает за чтение и запись данных в файлы.Оба этих класса реализуют простые интерфейсы Readable и Writable, что соответствует принципу разделения интерфейсов.
От базового класса Parser наследуются три конкретных реализации:
ParserSite_23MET: Основной парсер целевого сайта.
GoogleParser: Парсер, взаимодействующий с ScraperAPI для поиска в Google.
ParserProxyLib: Парсер для сбора бесплатных прокси.
Особняком стоит класс PreProcessor. Он не является парсером и не наследуется от класса Parser, что логично подчеркивает его роль в системе. Его задача — не сбор, а трансформация и очистка уже собранных данных. Он принимает на вход результат работы ParserSite_23MET и преобразует его в структурированный вид.
Такая архитектура обеспечивает высокую модульность, слабую связанность компонентов и хорошую расширяемость, что является залогом надежности и простоты  дальнейшей поддержки проекта.

3 Реализация
3.1 Реализация модуля сбора данных
Модуль сбора данных является центральным компонентом всей системы. Он реализован в виде класса ParserSite_23MET и отвечает за непосредственное взаимодействие с целевым сайтом 23met.ru, скачивание веб-страниц и первичное извлечение из них необработанной информации.
Работа модуля организована в виде последовательного конвейера, состоящего из двух основных этапов:
Скачивание страниц (метод save_data): На этом этапе модуль получает список URL-адресов, предварительно собранный модулем GoogleParser. Затем он асинхронно отправляет HTTP-запросы по каждому адресу, скачивает HTML-код страниц с прайс-листами и сохраняет их в локальную директорию 23MET_DATA для последующей обработки. Этот подход позволяет отделить этап получения данных от этапа их разбора, что повышает отказоустойчивость системы: в случае ошибки при разборе нет необходимости заново скачивать десятки страниц.
Извлечение данных (метод parsing): После того как все страницы сохранены, модуль последовательно считывает каждый HTML-файл. С помощью библиотеки BeautifulSoup он находит на страницах все таблицы, которые содержат необходимую информацию о продукции. Далее, модуль извлекает нужный текст, который содержит необходимую информацию. Для корректного объединения данных со всех страниц, сперва собираются все уникальные названия столбцов, что позволяет формировать единую структуру данных даже при различиях в таблицах на разных страницах.



Ключевые аспекты реализации:
Асинхронность: Для эффективного и быстрого скачивания большого количества страниц применяется асинхронный подход на базе библиотек asyncio и aiohttp. Это позволяет отправлять множество HTTP-запросов одновременно, не дожидаясь ответа от сервера на каждый предыдущий запрос, что кратно сокращает общее время работы.
Ограничение частоты запросов: Чтобы избежать блокировки со стороны сервера из-за слишком высокой активности, используется библиотека aiolimiter. Она позволяет установить ограничение на количество запросов в определенный промежуток времени (например, не более 100 запросов в 10 секунд), что обеспечивает стабильную и вежливую работу парсера.

Центральным методом логики извлечения данных является _parsing_one_site. Он принимает на вход путь к одному HTML-файлу, производит его разбор с помощью BeautifulSoup, находит все необходимые таблицы и преобразует их содержимое в словарь, где ключами являются названия столбцов, а значениями — списки данных. Этот метод также обрабатывает возможные пропуски и несоответствия в структуре таблиц.
Полный листинг кода модуля ParserSite_23MET представлен в Приложении А.
3.2 Механизм обхода блокировок
В процессе сбора данных система сталкивается с двумя разными типами потенциальных блокировок, требующими различных стратегий обхода: сложная защита поисковой системы Google и базовые ограничения на частоту запросов со стороны целевого сайта 23met.ru. В связи с этим в проекте реализован двухкомпонентный подход.
а) Основной механизм для обхода блокировок Google: Сбор URL-адресов с помощью прямого парсинга Google является нетривиальной задачей из-за продвинутых систем защиты поисковика, включающих CAPTCHA, JavaScript-проверки и блокировку по IP-адресам. Для решения этой проблемы модуль GoogleParser использует внешний сервис ScraperAPI. Данный сервис выступает в роли шлюза, который берет на себя всю сложность взаимодействия с Google: он автоматически управляет ротацией премиальных и резидентных прокси, решает CAPTCHA и использует браузеры с корректными заголовками. Это является основным и наиболее надежным механизмом в проекте, гарантирующим стабильное получение списка страниц для дальнейшего анализа.
б) Опциональный механизм для парсинга сайта 23 met.ru: Для снижения вероятности блокировки при скачивании большого количества страниц непосредственно с сайта 23met.ru предусмотрен дополнительный, но менее надежный механизм. Модуль proxyParser.py реализует логику сбора и проверки бесплатных прокси-серверов с общедоступного ресурса (proxylib.com). Основной парсер ParserSite_23MET может быть запущен с флагом использования этого списка прокси. В таком режиме каждый HTTP-запрос отправляется с нового IP-адреса, что помогает обойти простые лимиты на количество запросов с одного адреса. Важно отметить, что эффективность этого метода напрямую зависит от наличия и качества бесплатных прокси-серверов в открытом доступе в момент запуска, что не может быть гарантировано. Поэтому данный механизм является вспомогательной функцией, в то время как ScraperAPI остается ключевым элементом для обеспечения работоспособности всего пайплайна.
в) Реализация модуля предобработки данных: 
Данные, полученные на этапе парсинга, представляют собой "сырой" набор текстовой информации. Несмотря на табличную структуру, они не пригодны для прямого машинного анализа из-за множества проблем: наличия лишних пробелов, отсутствия стандартизации для пропущенных значений и, что самое важное, наличия композитных полей. Композитные поля — это колонки, в которых в виде одной строки смешано несколько разнородных признаков (например, в поле "Размер" могут быть и габариты и диаметр).
Для решения этой проблемы был разработан модуль PreProcessor (файл preProcessor.py), основной задачей которого является преобразование "сырых" данных в чистый, структурированный и атомарный формат. В качестве основного инструмента для манипуляции данными используется библиотека Pandas, которая предоставляет мощную и эффективную структуру данных DataFrame.
Процесс предобработки представляет собой конвейер из нескольких последовательных шагов, каждый из которых решает конкретную задачу.
a) Базовая очистка и стандартизация: Первым шагом является приведение данных к единому стандарту. Для этого были выполнены следующие действия:
Удаление лишних пробелов: Из каждой ячейки удаляются начальные и конечные пробелы. Это базовый, но критически важный шаг, так как " Ст3сп" и "Ст3сп" для машины являются разными значениями.
Нормализация пропусков: Пустые строки и различные текстовые обозначения отсутствия данных ('nan', 'н/д' и т.д.) заменяются на единый стандартный маркер numpy.nan. Это позволяет корректно использовать встроенные методы Pandas для статистического анализа и обработки пропущенных значений.

б) Feature Engineering: Это наиболее ценный этап предобработки, на котором неструктурированные текстовые поля разбираются на несколько новых, атомарных и машиночитаемых признаков. Для этого активно используются регулярные выражения (модуль re). Такой подход гораздо выгоднее ручного разбора, так как он позволяет создать гибкие и масштабируемые правила для тысяч строк данных.
Обработка колонки "Размер" : Данная колонка является самым ярким примером композитного поля. Для ее разбора был разработан статический метод parse_size, который последовательно применяет около десяти регулярных выражений, чтобы распознать различные форматы: Профили по ГОСТ (20К1, 16Б2), Европейские профили (IPE120, HE200A), Габаритные размеры (100х50х4), Листовой прокат с толщиной и размерами (5 1500х6000) и т. д. В результате одна колонка "Размер" порождает до пяти новых: Тип_продукции, Размер_A, Размер_B, Размер_C, Толщина и т.д. Такая декомпозиция критически важна, так как позволяет проводить количественный анализ (например, отфильтровать все листы толщиной более 3 мм), что было невозможно с исходными строковыми данными.
Обработка колонки "Сталь": Аналогично "Размеру", эта колонка часто содержит не только марку стали. Метод __process_steel_col извлекает из нее три новых признака:
Тип_материала: Определяет, является ли материал сталью, нержавеющей сталью, алюминием, латунью и т.д.
Основная_марка: Выделяет первую, наиболее значимую марку из перечислений (например, из "ст3сп/пс5" извлекается "ст3сп").
Свариваемость: Бинарный флаг (1 или 0), который указывает на наличие в марке символа "с", обозначающего свариваемость (например, А500С).Это обогащает данные, позволяя проводить более глубокий анализ и сегментацию (например, "сравнить среднюю цену на алюминиевые и латунные изделия").
Обработка колонки "ГОСТ" :  Строка стандарта (например, "ГОСТ 8732-78") разбирается на три компонента:  Тип_стандарта (ГОСТ, ТУ), Номер_стандарта (8732) и Год_стандарта (78). Это позволяет фильтровать продукцию по актуальности нормативного документа.

в) Трансформация и агрегация данных о ценах 
Особую сложность представляли данные о ценах, которые были распределены по нескольким колонкам с разными условиями ("Цена, розница", "Цена, до 1т" и т.д.).Метод __union_price_cols решает эту проблему следующим образом:
Динамически находит все колонки, содержащие цены.
Использует метод stack() библиотеки Pandas, чтобы "собрать" все значения цен из разных колонок в одну.
Для каждой позиции выбирается наиболее актуальная цена (в данном случае — последняя непустая).
Из полученной строки извлекается числовое значение цены, отделяясь от текстовых условий ("опт", "от 5т"), которые помещаются в отдельную колонку Условие_цены.
Обрабатывается особый случай "звоните", который преобразуется в бинарный флаг.
В результате вместо множества разреженных колонок с ценами создается единый, удобный для анализа набор признаков: Цена, Категория_цены, Условие_цены.

from base import Parser
from GoogleParser import GoogleParser

import aiohttp
import asyncio
import aiolimiter
from bs4 import BeautifulSoup

import os
import re
import pandas as pd
from typing import Union


class ParserSite_23MET(Parser):
    def __init__(self, 
                 base_url: str= "https://23met.ru",
                 proxy_list: list= None,
                 max_rate: int= 1,
                 time_period: int= 10):
        """
        Args:
            base_url (str, optional): доменное имя сайта. Defaults to "https://23met.ru".
            proxy_list (list, optional): Список прокси адресов. Defaults to None.
            max_rate (int, optional): Количество запросов за time_period. Defaults to 1.
            time_period (int, optional): Время за которое выполняется max_rate запросов. Defaults to 10.
        """

        super().__init__(base_url, proxy_list)
        self.__limiter = aiolimiter.AsyncLimiter(max_rate= max_rate,
                                                 time_period= time_period)
        DIR_NAME = "23MET_DATA"
        os.makedirs(DIR_NAME, exist_ok=True)
        self._dir_path = os.path.join(os.getcwd(), DIR_NAME) 
        self.__file_paths = None
        self.__unique_columns_name = None

    async def __get_and_save_site_data(self, 
                                       session: aiohttp.ClientSession, 
                                       url:str, 
                                       accept: str) -> None:
        """
        Получение html страницы и ее сохранение в файл  
        Args:
            session (aiohttp.ClientSession): Сессия
            url (str): url 
            accept (str, optional): типы файлов, которые клиент может принять (отображается браузером в header-e). Defaults to '*/*'.
        Returns:
            None
        """
        data = await self.get_html(session= session,
                                   url= url,
                                   accept= accept)
        if self.__checking(data):
            file_path = os.path.join(self._dir_path, url.split('/')[-1] + ".html")
            await self.put_file(path= file_path, data= data)
    
    async def __process_single_url_with_limiter(self,
                                                session: aiohttp.ClientSession, 
                                                url:str, 
                                                accept: str) -> None:
        """
        Получение html страницы и ее сохранение в файл, но с ограничением по количеству запросов за определенное время. Настройка кол-ва запросов за определенное время производится при инициализации объекта, с помощью параметров max_rate и time_period.
        Args:
            session (aiohttp.ClientSession): Сессия
            url (str): url 
            accept (str, optional): типы файлов, которые клиент может принять (отображается браузером в header-e). Defaults to '*/*'.
        Returns:
            None
        """
        async with self.__limiter:
            await self.__get_and_save_site_data(session=session, url=url, accept=accept)

    def __checking(self, 
                   html: str) -> bool:
        """
        Проверяет подходящий ли сайт или нет
        Args:
            html (str): код html страницы

        Returns:
            bool: True- подходит, False - неподходит
        """
        try:
            soup = BeautifulSoup(html, 'lxml')
        except TypeError:
            print(html, "тип None")
            return False
        title_tag = soup.find('title')
        if title_tag is not None and re.search(r"прайс-лист — 23MET.ru\Z", soup.find('title').text):
            return True
        return False

    async def save_data(self,
                        accept: str= '*/*',
                        with_update_sites_info: bool= False,
                        num: int= 100,
                        start: int= 0,
                        stop: int= 100) -> None:
        """
        Получает данные со всех сайтов (выданных Google-поиском) и сохраняет их в файлы 
        Args:
            accept (str, optional): типы файлов, которые клиент может принять (отображается браузером в header-e). Defaults to '*/*'
            with_update_sites_info (bool, optional): Просто обновить все сайты или полностью спарсить и Google-поиск?. Defaults to False.
            num (int, optional): Кол-во сайтов отображаемое Googl-ом на одной ее html странице . Defaults to 100.
            start (int, optional): С какого сайта начать отображать страницы в Google поиске. Defaults to 0.
            stop (int, optional): На каком сайте закончить отображать страницы в Google поиске. Defaults to 100.
        Returns:
            None
        """
        
        google_searcher = GoogleParser(query_for_browser= 'site:23met.ru прайс-лист')
        if with_update_sites_info:
            await google_searcher.run(num= num, 
                                      start= start, 
                                      stop= stop)
        else:
            await google_searcher.parsing()
        
        urls = google_searcher.get_urls()
            
        async with aiohttp.ClientSession() as session:
            tasks = []
            for url in urls:
                task = asyncio.create_task(self.__process_single_url_with_limiter(session= session, url= url, accept= accept))
                tasks.append(task)
            await asyncio.gather(*tasks)
    
    async def __get_one_site_unique_columns_name(self, 
                                                 file_path: str) -> Union[None, set]:
        """
        Ищет уникальное название колонки для одного сайта(file_path)
        Args:
            file_path (str): абсолютный путь к файлу

        Returns:
            Union[None, set]: Если None, то не нашлось уникальных названий колонок
        """

        html = await self.get_file(file_path)
        unique_column_names = set()
        if self.__checking(html):
            soup = BeautifulSoup(html, 'lxml')
            tables = soup.find_all('table', 'tablesorter')
            for table in tables:
                table: BeautifulSoup
                columns_name = table.find('thead').find_all('th')
                for column_name in columns_name:
                    unique_column_names.add(column_name.text)
            return unique_column_names
        else:
            return None
        
    async def __get_all_unique_columns_name(self) -> list:
        """
        Возвращает список всех уникальных названий колонок со всех сайтов
        Returns:
            list: список всех уникальных названий колонок со всех сайтов
        """
        tasks = []
        if not self.__file_paths:
            print("Не был инициализирован self.__file_paths. Создаю его сам")
            file_names = os.listdir(self._dir_path)
            self.__file_paths = [os.path.join(self._dir_path, file_name) for file_name in file_names]
        
        for file_path in self.__file_paths:
            tasks.append(asyncio.create_task(self.__get_one_site_unique_columns_name(file_path)))
        results = [result for result in await asyncio.gather(*tasks) if result]
        return list({item for result in results  for item in result})

    
    async def _parsing_one_site(self, 
                                file_path: str) -> Union[None, dict]:
        """
        Парсит 1 сайт(в file_path)
        Args:
            file_path (str): абсолютный путь к файлу

        Returns:
            Union[None, dict]: Если None, то не удалось спарсить сайт. dict - данные, которые удалось спарсить 
        """
        html = await self.get_file(file_path)
        data = dict()
        if not self.__unique_columns_name:
            print("Переменная self.__unique_columns_name не была инициализирована. Инициализирую ее!")
            self.__unique_columns_name = await self.__get_all_unique_columns_name()
        for column_name in self.__unique_columns_name:
            data[column_name] = []

        if self.__checking(html):
            soup = BeautifulSoup(html, 'lxml')
            tables = soup.find_all('table', 'tablesorter')

            for table in tables:
                table: BeautifulSoup
                columns_name = [column.text for column in table.find('thead').find_all('th')]
                trS_in_tbody = table.find('tbody').find_all('tr')
                for tr_in_tbody in trS_in_tbody:
                    tdS_in_tbody = tr_in_tbody.find_all('td')
                    for column_name, td_in_tbody in zip(columns_name, tdS_in_tbody):
                        if td_in_tbody.text == '':
                            data[column_name].append(None)
                        else:
                            data[column_name].append(td_in_tbody.text)
                    
                    for unique_column_name in self.__unique_columns_name:
                        if unique_column_name not in columns_name:
                            data[unique_column_name].append(None)
            return data
        
        else:
            return None
        

    def __delete_intermediate_data(self) -> None:
        """
        Удаление ненужных/промежуточных файлов

        Returns:
            None
        """
        for file_path in self.__file_paths:
            os.remove(file_path)

    async def parsing(self, 
                      with_save_result: bool= True) -> pd.DataFrame:
        """
        Парсинг данных из сайтов.
        Args:
            with_save_result (bool, optional): Сохранить ли результат в csv файл?. Defaults to True.

        Returns:
            pd.DataFrame: DataFrame - в котором храниться все спарщенные данные
        """
        file_names = os.listdir(self._dir_path)
        self.__file_paths = [os.path.join(self._dir_path, file_name) for file_name in file_names]
        self.__unique_columns_name = await self.__get_all_unique_columns_name()
        data = dict()
        for column_name in self.__unique_columns_name:
            data[column_name] = []

        main_df = pd.DataFrame(data)
        tasks = []
        for file_path in self.__file_paths:
            tasks.append(asyncio.create_task(self._parsing_one_site(file_path)))
        results = await asyncio.gather(*tasks)
        
        sites_without_needing_data= []
        df_s = dict()
        for index, result in enumerate(results):
            if not result:
                sites_without_needing_data.append(self.__file_paths[index])
            else:
                try:
                    df_s[self.__file_paths[index]] = pd.DataFrame(data= result)
                except ValueError:
                    print("Не все масивы одной длинны тут:", self.__file_paths[index])

        if sites_without_needing_data:
            print("Эти сайты не подходят под шаблон парсинга:", sites_without_needing_data)
        
        main_df = pd.concat(list(df_s.values()), ignore_index=True)
        main_df = main_df.sort_values(by= 'Наименование', ignore_index=True)
        if with_save_result:
            main_df.to_csv(os.path.join(self._dir_path, 'result.csv'))
        return main_df

import pandas as pd
import numpy as np
import re

class PreProcessor:

    def __init__(self, csv_file_path):
        self.__df = pd.read_csv(csv_file_path, index_col= 0)
        self.__del_space()
        self.__df = self.__df.replace(r'^\s*$', np.nan, regex=True) # Заменяем пустые строки в данных на тип NaN
        self.__preprocessing_size_col()
        self.__preprocessing_extra_size_col()
        self.__process_steel_col()
        self.__process_gost_col()
        self.__union_price_cols()
        
        self.__df = self.__df.replace(r'^\s*$', np.nan, regex=True)
        del self.__df['Доп. размер']
        del self.__df['Размер']
        del self.__df['Материал']

    @property
    def df(self):
        return self.__df
    
    def __del_space(self):
        """
        Удаляет ненужные пробелы
        """
        for col in self.__df.columns: 
            self.__df[col] = self.__df[col].str.strip()
    
    def __preprocessing_extra_size_col(self):
        """
        Обрабатывает колонку с доп. размером
        """
        col_name = 'Доп. размер'
        df = self.__df
        
        df[col_name] = df[col_name].astype(str).str.lower().str.strip()
        df[col_name] = df[col_name].replace(['', 'nan', 'н.д', 'нд', 'н/д', 'с н/д', 'с ост.'], np.nan)
        def extract_all_data(text):
            if pd.isna(text):
                return pd.Series([np.nan, np.nan, np.nan, np.nan], index=['Минимальная_длина', 'Максимальная_длина', 'Упаковка', 'Примечание_для_цены'])

            original_text = text

            packaging = np.nan
            if 'бухты' in text:
                packaging = 'бухты'
                text = text.replace('бухты', '').strip()
            elif 'размотка' in text:
                packaging = 'размотка'
                text = text.replace('размотка', '').strip()
            elif 'мотки' in text or 'розетты' in text:
                packaging = 'мотки/розетты'
                text = text.replace('мотки', '').replace('розетты', '').strip()
            
            length_primary = np.nan
            length_max = np.nan
            notes = text

            # Вариант 1: Диапазон "число-число" (e.g., "2-6", "3.4-3.7")
            range_match = re.search(r'(\d+\.?\d*)\s*-\s*(\d+\.?\d*)', text)
            if range_match:
                vals = sorted([float(range_match.group(1)), float(range_match.group(2))])
                length_primary, length_max = vals[0], vals[1]
                # Очищаем текст от найденного диапазона для примечаний
                notes = re.sub(r'\d+\.?\d*\s*-\s*\d+\.?\d*', '', text).strip()

            # Вариант 2: Размеры через "х" (e.g., "1.5х10", "1000х1000")
            elif 'х' in text:
                # Эти размеры не являются линейными, поэтому оставляем их в примечаниях
                # а поля длин оставляем пустыми.
                notes = original_text 
                
            # Вариант 3: Префикс "до" (e.g., "до 12")
            elif text.startswith('до '):
                numbers = re.findall(r'\b\d+(?:\.\d+)?\b', text)
                if numbers:
                    length_max = float(numbers[0])
                notes = text
            
            # Вариант 4: Стандартные числа (одиночные или списки)
            else:
                numbers_str = re.findall(r'\b\d+(?:\.\d+)?\b', text)
                if numbers_str:
                    numeric_values = sorted([float(n) for n in numbers_str])
                    if len(numeric_values) == 1:
                        length_primary = length_max = numeric_values[0]
                    elif len(numeric_values) > 1:
                        length_primary = numeric_values[0]
                        length_max = numeric_values[-1]
                    
                    notes = re.sub(r'[\d\.\s,]+', '', text).strip()

            if not notes or notes.isspace():
                notes = np.nan

            return pd.Series([length_primary, length_max, packaging, notes], index=['Минимальная_длина', 'Максимальная_длина', 'Упаковка', 'Примечание_для_цены'])

        extracted_data = df[col_name].apply(extract_all_data)
        
        for col in extracted_data.columns:
            self.__df[col] = extracted_data[col]

    def __union_price_cols(self):
        """
        Объединяет и обрабатывает колонки связанные с ценой.
        """
        cols_with_price = [col for col in self.__df.columns if re.search(r"Цена, ", col)]
        price_df = self.__df[cols_with_price]
        
        stacked_prices = price_df.stack()
        
        # Если цен вообще не нашлось, выходим, чтобы не было ошибок
        if stacked_prices.empty:
            self.__df['Цена'] = np.nan
            self.__df['Категория_цены'] = np.nan
            self.__df['Условие_цены'] = np.nan
            self.__df['Звоните'] = False
            self.__df.drop(columns=cols_with_price, inplace=True, errors='ignore')
            return
    
        final_prices = stacked_prices.reset_index()
        final_prices.columns = ['original_index', 'Категория_цены', 'temp_price']
    
        final_prices = final_prices.drop_duplicates(subset='original_index', keep='last')
        
        final_prices = final_prices.set_index('original_index')
        
        self.__df = self.__df.join(final_prices)
    
        PRICECOL = 'Цена'
        CALLCOL = 'Звоните'
        
        is_call = self.__df['temp_price'].str.lower() == 'звоните'
        self.__df[CALLCOL] = is_call.fillna(False)
        
        self.__df.loc[self.__df[CALLCOL], 'temp_price'] = np.nan
    
        pattern = r'^(?P<Цена>[\d\s.,]+)(?:\s+(?P<Условие_цены>.+))?$'
        extracted_data = self.__df['temp_price'].str.extract(pattern)
        
        self.__df[PRICECOL] = extracted_data['Цена'] if not extracted_data.empty else np.nan
        self.__df['Условие_цены'] = extracted_data['Условие_цены'] if not extracted_data.empty else np.nan
        
        self.__df[PRICECOL] = self.__df[PRICECOL].apply(
            lambda x: float(str(x).replace(" ", "").replace(",", ".")) if pd.notna(x) else np.nan
        )
    
        self.__df['Категория_цены'] = self.__df['Категория_цены'].str.replace('Цена, ', '', regex=False)
    
        self.__df.drop(columns=cols_with_price + ['temp_price'], inplace=True, errors='ignore')

    def __preprocessing_size_col(self):

    @staticmethod
    def parse_size(size_str):
        """
        Парсит сложное строковое значение из столбца "Размер" 
        и возвращает словарь с извлеченными компонентами.
        """
        result = {}
        
        if pd.isna(size_str) or not str(size_str).strip():
            return result

        s = str(size_str).strip()
        s_clean = s.replace(',', '.').replace('х', 'x') # Унификация разделителей

        # Шаблон 1: Профили по ГОСТ/СТО (20К1, 16Б2, 24М, 40К5, 18К2В)
        match = re.fullmatch(r'(\d+)([А-Яа-я]+)(\d+)([А-Яа-я]?)', s, re.IGNORECASE)
        if match:
            result = {
                'Тип_продукции': 'Профиль ГОСТ/СТО',
                'Типоразмер': int(match.group(1)),
                'Марка': f"{match.group(2).upper()}{match.group(3)}{match.group(4).upper()}"
            }
            return result
        # Шаблон 2: Европейские профили (IPE120, HE200A, UPN120)
        match = re.fullmatch(r'(IPE|HE|UPN|I|H|U)([A-Z]*)(\d+)([A-Z]*)', s, re.IGNORECASE)
        if match:
            result = {
                'Тип_продукции': 'Европрофиль',
                'Марка': f"{match.group(1).upper()}{match.group(2)}{match.group(3)}{match.group(4)}",
                'Размер_A': float(match.group(3))
            }
            return result

        # Шаблон 3: Рельсы (Р33, КР70)
        match = re.fullmatch(r'(Р|КР|К)(\d+)', s, re.IGNORECASE)
        if match:
            result = {
                'Тип_продукции': 'Рельс',
                'Марка': f"{match.group(1).upper()}{match.group(2)}",
                'Типоразмер': int(match.group(2))
            }
            return result

        # Шаблон 4: Профнастил/Сетки с префиксом (С20 0.5x1100(1150), ПН 28x27x0.5)
        match = re.match(r'^([А-Яа-я]+)\s+(.*)', s_clean)
        if match:
            prefix, rest = match.groups()
            result = {
                'Тип_продукции': 'Профнастил/Сетка',
                'Марка': prefix,
                'Примечание_для_размера': rest
            }
            return result
        
        # Шаблон 5: Электроды/Марки (Omnia-46 4, E308L-16 2х350)
        match = re.match(r'([A-Za-z]+-?\d+L?-\d*)\s*(.*)', s_clean)
        if match:
            return {
                'Тип_продукции': 'Электрод/Марка',
                'Марка': match.group(1),
                'Примечание_для_размера': match.group(2) if match.group(2) else np.nan
            }

        # Шаблон 6: Листовой/рулонный прокат с толщиной и размерами/диапазонами
        # (5 1500х6000, 0.5 9-1000, 508 1200x2000-3500)
        match = re.match(r'^([\d\.]+)\s+(.*)', s_clean)
        if match:
            potential_thickness, rest = match.groups()
            # Проверяем, что дальше идут размеры через 'x' или диапазон
            if 'x' in rest or '-' in rest:
                result = {'Тип_продукции': 'Лист/Рулон', 'Толщина': float(potential_thickness)}
                
                range_match = re.search(r'([\d\.]+)-([\d\.]+)', rest)
                if range_match:
                    result['Диапазон_min'] = float(range_match.group(1))
                    result['Диапазон_max'] = float(range_match.group(2))
                    result['Примечание_для_размера'] = rest
                else:
                    dims = [float(d) for d in re.findall(r'[\d.]+', rest)]
                    if len(dims) > 0: result['Размер_A'] = dims[0]
                    if len(dims) > 1: result['Размер_B'] = dims[1]
                    if len(dims) > 2: result['Размер_C'] = dims[2]

                return result
        # Шаблон 7: Габариты (100х50х4, 4x120)
        if 'x' in s_clean:
            try:
                dims = [float(d) for d in re.findall(r'[\d.]+', s_clean)]
                result = {'Тип_продукции': 'Габарит'}
                if len(dims) >= 1: result['Размер_A'] = dims[0]
                if len(dims) >= 2: result['Размер_B'] = dims[1]
                if len(dims) >= 3: result['Размер_C'] = dims[2]
                return result
            except ValueError:
                # Не удалось преобразовать в числа, значит, это сложный случай
                pass

        # Шаблон 8: Число с буквой У/П (10У)
        match = re.fullmatch(r'(\d+\.?\d*)([УП])', s_clean, re.IGNORECASE)
        if match:
            return {
                'Тип_продукции': 'Уголок/Полоса',
                'Размер_A': float(match.group(1)),
                'Марка': match.group(2).upper()
            }

        # Шаблон 9: Дробь или сложный текст (33x11/30x2)
        if '/' in s_clean or re.search(r'[А-Яа-я]', s_clean): # Если есть слэш или кириллица
            return {'Тип_продукции': 'Нестандартный', 'Примечание_для_размера': s}
            
        # Шаблон 10: Простое число (последний вариант)
        try:
            return {'Тип_продукции': 'Число', 'Размер_A': float(s_clean)}
        except ValueError:
            return {'Тип_продукции': 'Нераспознанный', 'Примечание_для_размера': s}
        

    def __process_steel_col(self):
        """
        Обрабатывает колонку "Сталь", извлекая из неё новые полезные признаки.
        """
        self.__df.rename(columns={'Сталь': 'Материал'}, inplace=True)
        material_clean = self.__df['Материал'].str.lower().str.strip().fillna('не указан')

        # --- Функция 1: Определяем тип материала ---
        def get_material_type(mat_str):
            if 'aisi' in mat_str or re.search(r'\d*х\d+н\d+', mat_str):
                return 'Нержавеющая сталь'
            if any(x in mat_str for x in ['амг', 'ад', 'д16', 'в95', 'ак4', 'ак6']):
                return 'Алюминиевый сплав'
            if any(x in mat_str for x in ['лс', 'л6']):
                return 'Латунь'
            if 'бр' in mat_str:
                return 'Бронза'
            if 'чугун' in mat_str:
                return 'Чугун'
            if 'м1' in mat_str or 'м2' in mat_str or 'м3' in mat_str:
                 return 'Медь'
            if mat_str == 'не указан':
                return 'Не указан'
            return 'Сталь'
        
        self.__df['Тип_материала'] = material_clean.apply(get_material_type)

        # --- Функция 2: Выделяем основную марку ---
        def get_primary_grade(mat_str):
            if mat_str == 'не указан':
                return 'не указан'
            parts = re.split(r'[\s/,-]+', mat_str)
            return parts[0]

        self.__df['Основная_марка'] = material_clean.apply(get_primary_grade)

        # --- Функция 3: Флаг свариваемости ---
        # Ищем марки вида А500С, С345С и т.д.
        self.__df['Свариваемость'] = material_clean.apply(
            lambda x: 1 if re.search(r'^(а|в|с)\d+с$', x) else 0
        )
        
    def __process_gost_col(self):
        """
        Обрабатывает колонку ГОСТ, извлекая из неё тип, номер и год стандарта.
        """
        col_name = 'ГОСТ'
        if col_name not in self.__df.columns:
            return
        gost_series = self.__df[col_name].fillna('не указан').str.upper().str.replace(' ', '')
        pattern = re.compile(r'^(?P<type>[А-Я]+)(?P<number>[\d.-]+)(?:-(?P<year>\d{2,4}))?$')
        extracted_data = gost_series.str.extract(pattern)
        extracted_data.columns = ['Тип_стандарта', 'Номер_стандарта_raw', 'Год_стандарта']
        self.__df['Тип_стандарта'] = extracted_data['Тип_стандарта'].fillna('не указан')
        self.__df['Номер_стандарта'] = extracted_data['Номер_стандарта_raw'].str.replace(r'-\d{2,4}$', '', regex=True)
        self.__df['Год_стандарта'] = extracted_data['Год_стандарта'].astype(float).fillna(0).astype(int)

    def save_data(self, path: str):
        """
        Сохранение данных в csv файл
        Args:
            path (str): абсолютный путь куда нужно сохранять данные
        """
